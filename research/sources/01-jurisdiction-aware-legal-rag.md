# Jurisdiction Handling in Legal/Regulatory AI, LLM and RAG Systems

## 1. Commercial legal AI products

**Harvey.** Harvey is the most transparent of the vendors about jurisdiction architecture. Its post ["Using Agents to Scale Harvey's Knowledge Sources"](https://www.harvey.ai/blog/using-agents-to-scale-harveys-knowledge-sources) describes a **declarative per-jurisdiction configuration object**: "the domains to search, the filter hierarchy for narrowing queries, the permissions required for access, and optional agent instructions." Jurisdiction-specific sources are exposed to the agent as **parameterized tools** — the agent selects the jurisdiction, and the config determines which curated sources/filters are used — rather than one agent per jurisdiction (this preserves multi-turn context). An "intake engine" performs "automated jurisdiction mapping" of new sources, and an evaluation pipeline synthesizes scenarios per jurisdiction before launch. Coverage reportedly grew from 6 to 60+ jurisdictions and 20 to 400+ sources since Aug 2025. A companion post on [agentic search](https://www.harvey.ai/blog/how-agentic-search-unlocks-legal-research-intelligence) says outputs are limited "to jurisdiction-specific databases." Infrastructure notes ([ZenML case write-up](https://www.zenml.io/llmops-database/enterprise-grade-rag-systems-for-legal-ai-platform)) mention LanceDB with metadata filtering at 15M rows and hybrid sparse/dense retrieval. *Known:* config-driven jurisdiction scoping + agent-selected filters. *Speculated:* exact filter taxonomy and version handling are not published.

**Thomson Reuters Westlaw / CoCounsel.** Jurisdiction is a first-class, user-selected filter inherited from classic Westlaw. **AI Jurisdictional Surveys** requires the user to tick federal/any of 50 states via checkboxes and then returns per-jurisdiction differences with **KeyCite flags** (currency/negative treatment) and links to authority ([Westlaw Advantage features](https://legal.thomsonreuters.com/en/products/westlaw-advantage/features); [USC libguide](https://lawlibguides.usc.edu/c.php?g=1447399&p=10757364)). The new agentic CoCounsel Legal (built on the Claude Agent SDK) uses Westlaw features — Key Numbers, KeyCite, statute annotations — as modular tools for a planning agent ([TR Labs "Deep Research" post](https://medium.com/tr-labs-ml-engineering-blog/deep-research-in-westlaw-and-cocounsel-building-agents-that-research-like-lawyers-508ad5c70e45); [LawSites](https://www.lawnext.com/2025/08/thomson-reuters-launches-cocounsel-legal-with-agentic-ai-and-deep-research-capabilities-along-with-a-new-and-final-version-of-westlaw.html)). *Known:* explicit user-side jurisdiction selection plus editorial citator metadata for currency. *Not published:* how the agent decides jurisdiction when the user does not specify it.

**LexisNexis Lexis+ AI / Protégé.** Protégé offers two modes for statutory surveys: select up to three jurisdictions, or run a "full survey" across all states ([Stanford CSLAW paper](https://arxiv.org/pdf/2603.03300)). The 2026 "Legal Intelligence Engine" rebuild uses an Orchestrator Agent + Legal Research Agent etc.; before execution it **shows the plan to the user, who can correct the jurisdiction** or add/remove sources ([LawSites, Aug 2026](https://www.lawnext.com/2026/08/lexisnexis-unveils-legal-intelligence-engine-rebuilding-protege-around-dynamic-agentic-orchestration.html)). Personalization settings store the user's jurisdiction and practice area ([Pulse2](https://pulse2.com/lexisnexis-legal-ai-platform-expanded/)). Shepard's is used as the currency signal. *Pitfall reported:* answers changed for 12 of 24 questions when the same query was run as 3-state vs. all-state ([2603.03300](https://arxiv.org/html/2603.03300)).

**vLex Vincent AI (Clio).** Pure RAG over a ~1B-document corpus with vector search ([vLex support](https://support.vlex.com/vincent-by-vlex/vincent/security-privacy-and-compliance/understanding-the-ai-models-used-by-vincent)). Jurisdiction is a **user-managed default** ("Managing Your Default Jurisdictions") and an explicit selector in the **Compare Jurisdictions** workflow (up to 15 jurisdictions/sub-jurisdictions incl. US states) ([docs](https://support.vlex.com/vincent-by-vlex/vincent/core-workflows/compare-jurisdictions)). Cross-language: the English query is translated and run in the home-country language ([LawSites](https://www.lawnext.com/2025/02/exclusive-with-its-latest-release-out-today-vlexs-vincent-ai-adds-multi-modal-capabilities-litigation-workflows-and-coverage-for-four-new-countries.html)). Coverage is documented per jurisdiction ("Viewing Vincent Coverage by Jurisdiction").

**Legora.** Says it uses "structured, jurisdiction-aware data, ranked by authority," investigates sources in parallel across jurisdictions and verifies findings against primary law ([Legora legal research](https://legora.com/product/legal-research); [content imperative post](https://legora.com/blog/the-legal-content-imperative-building-useful-legal-ai)). After acquiring Qura it claims "structured, AI-native legal databases" beyond plain RAG ([newsroom](https://legora.com/newsroom/legora-acquires-qura-to-build-the-world%E2%80%99s-leading-ai-native-legal-research-platform)). Uses Elastic for search ([Elastic customer story](https://www.elastic.co/customers/legora)). Architecture details are marketing-level only.

**Spellbook, Luminance, Casetext.** These are contract-review tools; jurisdiction appears mainly as *governing-law clause detection* and "review against a specific jurisdiction/playbook" ([Spellbook](https://spellbook.com/learn/ai-legal-document-review)), not as retrieval scoping over primary law. Casetext's CoCounsel was folded into TR. No published jurisdiction-routing architecture found for any of them.

**Swiss/European vertical products.** DeepLegal (DeepCloud) syncs all cantonal law collections via LexFind and federal law from Fedlex ([DeepCloud](https://www.deepcloud.swiss/en/newsroom/article/introducing-deeplegal-ai-powered-legal-research-for-swiss-law/)); Omnilex includes federal and cantonal decisions/statutes ([omnilex.ai](https://omnilex.ai/en)). A Swiss comparison guide notes vendors are assessed on "multilingualism, cantonal case law and source fidelity" ([getcasus](https://www.getcasus.com/blog/legal-ai-switzerland-comparison-2026)).

## 2. Academic work

**Stanford RegLab, "Hallucination-Free?"** (Magesh et al., JELS 2025; [arXiv](https://arxiv.org/abs/2405.20362); [RegLab page](https://reglab.stanford.edu/publications/hallucination-free-assessing-the-reliability-of-leading-ai-legal-research-tools/)). 34.7% of the 202 queries were "jurisdiction or time-specific." Accuracy on those: Lexis+ AI 65%, Westlaw AI-AR 41%, Ask Practical Law 19%; hallucination rates were slightly *higher* than for general questions. Documented failure types: **jurisdiction confusion / authority-hierarchy violations** (Westlaw claimed a US Supreme Court case was reversed by the Nebraska Supreme Court on federal law), **temporal misapplication** (Lexis+ described the pre-*Dobbs* "undue burden" standard as current), and "inapplicable authority" (23–38% of hallucinations). The authors' implication: relevance-only retrieval is insufficient; systems need **non-textual filters** for jurisdiction, time and authority level.

**"Benchmarking Legal RAG: The Promise and Limits of AI Statutory Surveys"** (Afane, Hariri, Ouyang, Ho; CSLAW '26; [arXiv 2603.03300](https://arxiv.org/abs/2603.03300)). LaborBench: DOL attorneys' 50-state unemployment-insurance analysis. Results: custom STARA 83% (92% after correcting ground-truth omissions), standard RAG 70%, Lexis+ AI 64%, Westlaw AI 58%. STARA processes **state by state**, preserves statutory hierarchy, augments provisions with definitions/cross-references, optionally applies RegEx pre-filters, then LLM relevance classification. Reported pitfalls: Westlaw false-positived 41 states as differing from federal definitions; Lexis+ gave inconsistent answers across survey modes; a 300-character prompt limit hindered precise scoping. Design principles include specifying temporal scope and handling of expired provisions, and including regulations/guidance, not just statutes.

**Temporal validity.**
- *Temporal Misgrounding in Legal RAG* (French tax code, 32,436 article-versions, 1938–2031; [arXiv 2608.09393](https://arxiv.org/abs/2608.09393v1)): static RAG retrieved the date-applicable version **0%** of the time (2.7% answer accuracy); a **versioned multi-version index** with date-aware retrieval reached **98.3%**.
- *Asking For An Old Friend* (312 German statutory QA pairs from Buzer.de; [arXiv 2605.23497](https://arxiv.org/abs/2605.23497)): diagnoses post-cutoff staleness and recency bias; extracting an **as-of date** from the query and filtering the corpus to the validity window materially improves accuracy — temporal validity should be a *hard constraint*.
- *SAT-Graph RAG* ([arXiv 2505.00039](https://arxiv.org/html/2505.00039v5); action API [2510.06002](https://arxiv.org/html/2510.06002v1)): LRMoo-based ontology (Norm → Component → Temporal Version → Language Version) with URN LEX identifiers encoding jurisdiction (`urn:lex:br:federal:...`), deterministic point-in-time retrieval and provenance chains. Qualitative evaluation only.

**Metadata and chunking.**
- *Metadata-Enriched RAG + DPO* ([arXiv 2603.19251](https://arxiv.org/abs/2603.19251)): chunks prefixed with local summary, document name and **jurisdiction**; document-retrieval mismatch on MAUD fell from 87% to 13%, Australian legal QA span recall +35–40%. Jurisdiction's isolated contribution was not measured.
- *Towards Reliable Retrieval in RAG for Large Legal Datasets* ([arXiv 2510.06999](https://arxiv.org/abs/2510.06999)): names **Document-Level Retrieval Mismatch** (pulling from the wrong but structurally similar document) and mitigates it with Summary-Augmented Chunking; generic summaries beat legal-expert-crafted ones.
- *N2I-RAG* ([arXiv 2605.26926](https://arxiv.org/pdf/2605.26926)): agentic pipeline that extracts date/jurisdiction/theme metadata to JSON and uses metadata retrieval alongside text search.
- *Domain-Partitioned Hybrid RAG for India* ([arXiv 2602.23371](https://arxiv.org/abs/2602.23371)): separate indexes per source type, LLM orchestrator routes queries; 70% vs 37.5% for flat RAG.
- *CoAL-RAG* ([arXiv 2608.17536](https://arxiv.org/abs/2608.17536)): complexity-aware switching between semantic and keyword retrieval; claims cross-jurisdiction generalization (Chinese/English).

**Benchmarks.** [LegalBench-RAG](https://arxiv.org/abs/2408.10343) ([GitHub](https://github.com/zeroentropy-ai/legalbenchrag)) tests precise span retrieval but is largely jurisdiction-agnostic (contracts, privacy policies). [CLERC](https://arxiv.org/abs/2406.17186) is US federal case law only. [LEXTREME](https://arxiv.org/pdf/2503.04305) / MultiLegalPile are multilingual, multi-jurisdiction classification corpora. [ClaimRAG-LAW](https://arxiv.org/html/2605.21071v2) (GDPR + French civil code) includes a "jurisdiction or time-specific" category and finds wrong claims mostly come from *partially relevant* chunks spanning article boundaries; BM25 beat dense retrievers. [Place Matters](https://arxiv.org/abs/2511.06700) shows closed-book LLM hallucination varies strongly by location (LA 45%, London 55%, Sydney 61%; 100% on the Australian Residential Tenancies Act) — evidence that parametric knowledge cannot be trusted for local law. [LexAgentHallu](https://arxiv.org/html/2609.09754) profiles hallucinations in legal agents. The [Vals Legal AI Report](https://www.vals.ai/industry-reports/vlair-2-27-25) is task-based and does not isolate jurisdiction; secondary sources cite a ~14-point drop on multi-jurisdictional surveys ([AI Law Librarians](https://www.ailawlibrarians.com/2026/02/19/what-the-science-says-about-hallucinations-in-legal-research/)).

No paper was found proposing a dedicated "which jurisdiction governs this document" classifier; jurisdiction is nearly always taken from **source provenance** (which official portal/court the document came from) rather than predicted from text ([NLP-for-law survey](https://arxiv.org/pdf/2410.21306)).

## 3. Techniques observed (with evidence)

| Technique | Where seen | Evidence strength |
|---|---|---|
| **Explicit user jurisdiction selector / default jurisdiction** | Westlaw (checkboxes), Lexis (≤3 or all), Vincent (default + up to 15), Harvey (agent-selected param) | Universal in commercial tools; the plan-preview-and-correct step in Lexis is the newest variant |
| **Metadata-filtered hybrid search** (canton/court/date/language fields) | Harvey (LanceDB metadata filters), OpenCaseLaw MCP (`court`, `canton`, `decision_date`, `language`, `chamber`), Corlytics/Compliance.ai tagging | Proven in production; papers show metadata-in-chunk also lifts recall |
| **Per-jurisdiction partitioned indexes + query routing** | STARA (state-by-state), India domain-partitioned RAG, SuzieLaw (provider per jurisdiction), Harvey config objects | Strong: STARA beat commercial tools; routing errors are the main risk when jurisdiction is inferred |
| **Provenance-based jurisdiction assignment** (source portal = jurisdiction) | Open US Law (`us/co/statutes/...` IDs), Fedlex/RIS/EUR-Lex MCP servers | Simplest and most reliable; avoids classification error |
| **Versioned corpora / as-of-date filtering** | FiscalQA Pro (0%→98.3%), German statutory QA, SAT-Graph RAG, Open US Law `act_status` + quarterly snapshots, OpenCaseLaw `get_legislation` version history | Strongest single quantitative result in the literature |
| **Citator / status metadata as currency signal** | KeyCite, Shepard's Verify, `act_status` (in_force/repealed) | Editorial, expensive, but what the incumbents rely on |
| **Knowledge graphs of legal hierarchy / citations** | SAT-Graph RAG (norm hierarchy, temporal versions), OpenCaseLaw 10M-edge citation graph + appeal chains, EUR-Lex CELLAR graph incl. national transposition ([eur-lex-mcp-server](https://github.com/cyanheads/eur-lex-mcp-server)), Clausematch KG, [LegalGraphRAG](https://arxiv.org/html/2605.28120v1) | Promising; mostly qualitative evaluation. No found system encodes lex superior / lex specialis conflict rules explicitly |
| **Hierarchy-preserving chunking + definition/cross-ref augmentation** | STARA, SAC, ClaimRAG-LAW finding on article-boundary noise | Proven to reduce document-level mismatch |

## 4. RegTech

- **Compliance.ai**: ML models supervised by 130+ regulatory specialists ("expert-in-the-loop") classify documents from 8,000+ sources across 230+ jurisdictions by agency, topic and obligation; users pre-configure agencies/jurisdictions of interest ([compliance.ai](https://www.compliance.ai/solution/regulatory-intelligence/)).
- **Ascent**: starts with a **Regulatory Map** (explicit definition of jurisdictions, regulators and rule sections that apply to the firm), then extracts each obligation as an individual object into an Obligations Inventory ([Ascent](https://www.ascentregtech.com/blog/automate-identification-of-your-regulatory-obligations/)).
- **Clausematch**: open-source regulatory knowledge graph (built with ADGM's FSRA) tagging regulatory concepts/obligations/expectations so regulators publish machine-readable rule structure ([A-Team](https://a-teaminsight.com/blog/clausematch-releases-open-source-knowledge-graph-framework-for-regulatory-reporting/)).
- **Corlytics**: "Universal Regulatory Taxonomy" and Taxonomy Manager; built the FCA's intelligent handbook with 3,000+ metadata tags; maps obligations to the firm's legal entities, products and controls with SME validation ([Corlytics obligations](https://www.corlytics.com/solutions/regulatory-obligations-management/); [taxonomy manager](https://www.corlytics.com/solutions/taxonomy-manager-for-regulators/)).
- **4CRisk** (acquired by CUBE, Feb 2026): specialised language models mapping policies to obligations/controls ([PRNewswire](https://www.prnewswire.com/apac/news-releases/cube-acquires-silicon-valley-regtech-4crisk-delivering-next-generation-compliance-and-risk-mapping-automation-302692391.html)).
- **Regology / Reggi**: 16M+ laws across 135+ countries; obligations mapped to policies; answers "fine-tuned to the company's business activities" ([Regology](https://www.regology.com/platform)).

Common RegTech pattern: jurisdiction is an **applicability profile** set up front (entities, licences, products, countries), and documents are tagged by regulator/jurisdiction at ingestion by ML + human review; retrieval is then filtered by profile. This is the inverse of legal research tools, where jurisdiction is chosen per query.

## 5. Open-source multi-jurisdiction projects

- [firelex/suzielaw](https://github.com/firelex/suzielaw): 19 jurisdictions via 22 official providers (RIS, Fedlex, EUR-Lex/CURIA, Légifrance, gesetze-im-internet, BOE, Normattiva, CourtListener/eCFR…) behind three uniform tools; jurisdiction from an explicit parameter or inferred from the query ("Article 1382 Code Civil" → Légifrance); optional sqlite-vec RAG.
- [jonashertner/opencaselaw](https://github.com/jonashertner/opencaselaw): Swiss corpus, 1M+ decisions, 5.5k federal + 15.6k cantonal laws, all 26 cantons, structured `canton`/`court`/`decision_date`/`language` fields, cross-language cantonal search, version history, appeal chains, 10M-edge citation graph, 42 MCP tools.
- [Vaquill-AI/open-us-law](https://github.com/Vaquill-AI/open-us-law): 2.9M sections of US Code, CFR, 50-state codes/regs/constitutions in one 24-column schema with hierarchical IDs encoding jurisdiction, `act_status`, and dated quarterly snapshots; cross-refs into USC/CFR.
- Austria: [cyanheads/ris-austria-mcp-server](https://github.com/cyanheads/ris-austria-mcp-server), [Honeyfield-Org/ris-mcp-ts](https://github.com/Honeyfield-Org/ris-mcp-ts), [Ansvar-Systems/Austrian-law-mcp](https://github.com/Ansvar-Systems/Austrian-law-mcp) — federal plus all 9 Länder.
- EU: [cyanheads/eur-lex-mcp-server](https://github.com/cyanheads/eur-lex-mcp-server) (CELLAR graph incl. national transposition measures, EuroVoc), [Aptus-AI/chat-eur-lex](https://github.com/Aptus-AI/chat-eur-lex), [legal-text-ragifier](https://github.com/pastpap/legal-text-ragifier).
- Lists: [rnckp/awesome-open-legal-switzerland](https://github.com/rnckp/awesome-open-legal-switzerland), [openlegaldata/awesome-legal-data](https://github.com/openlegaldata/awesome-legal-data), [Vaquill-AI/awesome-legaltech](https://github.com/Vaquill-AI/awesome-legaltech).
- No mature open-source project was found for German Länder law specifically; Germany is covered only at federal level (gesetze-im-internet, OpenLegalData).

## Key takeaways

1. **Nobody infers jurisdiction from document text at scale.** Every serious system assigns jurisdiction at ingestion from *provenance* (the official portal, court, gazette) and encodes it in IDs/metadata (Open US Law paths, `urn:lex`, OpenCaseLaw `canton`). Build the corpus per-source, not per-classifier.
2. **Query-side jurisdiction is made explicit, not guessed.** Commercial tools use selectors, stored defaults, or an agent-proposed plan the user can correct (Lexis). Where inference is used (Harvey, SuzieLaw), it is a tool *parameter* the agent must fill, so it is auditable. The Stanford errors show what happens when relevance ranking alone decides.
3. **Metadata-filtered hybrid search + partitioned indexes is the proven core.** STARA's state-by-state processing beat Westlaw/Lexis; metadata-enriched chunks cut wrong-document retrieval from 87% to 13%.
4. **Temporal validity is a hard filter, not a ranking feature.** Static RAG retrieved the right version 0% of the time; a versioned index with an as-of date reached 98%. Store `valid_from`/`valid_to` (or `act_status` + snapshot date) on every provision and extract an as-of date from the query.
5. **Authority hierarchy needs explicit modelling.** Reported pitfalls — a state court "reversing" SCOTUS, panel vs en banc confusion, federal vs state definitional mismatches — are hierarchy errors. Graph approaches (SAT-Graph, citation/appeal chains) address this, but none found encodes lex superior/specialis rules; that remains a gap.
6. **Chunk on legal structure, not tokens.** Chunks spanning several short articles were the main source of incorrect claims in ClaimRAG-LAW; hierarchy-preserving segmentation with definitions and cross-references attached is what STARA and SAC rely on.
7. **Verify against a currency signal.** Incumbents lean on KeyCite/Shepard's; open alternatives are status fields and change feeds (LexFind, RIS, Fedlex SPARQL).
8. **Pitfalls to expect:** inconsistent answers depending on how many jurisdictions are selected; prompt-length limits that block precise scoping; thin coverage for local/municipal law (Place Matters: up to 100% hallucination); opacity of commercial coverage (both Stanford papers note they cannot tell database gaps from retrieval faults). Publish coverage per jurisdiction and return "no authority found" rather than a neighbour's rule.
